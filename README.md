# Qwythos Code

手元のパソコンで動く、自律コーディングの相棒です。
お願いを日本語で書くと、自分でファイルを探し、読み、書き換え、テストを走らせて、結果を報告します。
**考えるのは手元のモデル**（Ollama 上の qwythos / qwen3 など）で、あなたのコードが学習に使われることはありません。

調べものが要るときだけ、外に出ます（→[ネットにつながる部分](#ネットにつながる部分)）。
出ていくのは検索の言葉と URL だけで、**ファイルの中身も会話の履歴も送りません**。
ログインが要るページは、あなたが手でログインした本物のブラウザで開きます
（→[ログインが要るサイトを読ませる](#ログインが要るサイトを読ませる)）。**パスワードは受け取りません。**
`--no-net` を付ければ完全に手元だけで動きます。

```
❯ テストが落ちてるので直して

✻ 6.2 秒考えました
● run_command(npm test)
  ⎿ 終了コード 1
● read_file(sum.js)
  ⎿ 3 行を読み込み
● edit_file(sum.js)
  ⎿ 1 か所を置き換え
● run_command(npm test)
  ⎿ 終了コード 0

sum.js の引き算を足し算に直しました。npm test は通っています。
```

## 必要なもの

- Node.js 20 以上
- [Ollama](https://ollama.com) が動いていること（`ollama serve`）
- モデル: `qwythos:latest`（無ければ、入っているものから自動で選びます）

**本体は Node の標準機能だけで動きます。**外から持ってきた部品は1つも使っていません。

`npm install` が要るのは、次の2つを使うときだけです。どちらも入れなければ、
**その道具が渡らないだけ**で、他はすべて動きます（呼べない道具をモデルに見せない、が方針です）。

| 入れるもの | 何のために | 入れないと |
| :--- | :--- | :--- |
| `typescript` | TypeScript / JavaScript の[意味検索](#意味でコードを探すlsp) | `find_symbol` が渡らない（Rust・C++ は別途の言語サーバーで動く） |
| `playwright` | [ログインが要るサイト](#ログインが要るサイトを読ませる)を読む | `browse` と `/login` が渡らない |

どちらも `optionalDependencies` なので、`npm install` は失敗しません。

## 使い始める

```bash
# どこからでも qwc で呼べるようにする
cd ~/qwythos-code
npm link          # もしくは: alias qwc="node ~/qwythos-code/bin/qwc.mjs"

# 作業したいフォルダで起動
cd ~/my-project
qwc
```

`❯` が出たら、そのまま日本語でお願いを書いて Enter。

## 一回だけ実行する

自動化やシェルスクリプトから使う形です。

```bash
qwc -p "README のタイポを直して" --yolo
```

`-p` では確認に答えられないため、書き換えまで任せるなら `--yolo` が要ります。

## 安全のしくみ

自律的に動くものなので、勝手に壊さないための歯止めを3つ入れてあります。

1. **作業フォルダの外は触れません。** 起動したフォルダより上には出られません（`--allow-outside` で解除）。
2. **書き換え・コマンド実行・ネット接続は、実行前に確認します。** 差分や検索語を見てから y / n を選べます。
   `a` を押すと、以後そのセッション中は同じ種類を自動で許可します。
3. **読むだけのコマンドは確認なしで通します。** `ls` `cat` `git status` などの安全な一覧だけが対象で、
   `;` や `|` や `>` が混ざっていたら安全とはみなしません。

> **2026-08-06 に直した不具合。** それまで道具すべてが「確認なし」の設定になっていて、
> ここに書いた確認が**一度も出ていませんでした**（確認のしくみ自体は完成しているのに、呼ばれていなかった）。
> 書き換えもコマンド実行も、黙って実行されていました。
> 同じことが再発しないよう、道具ごとの設定値を検証（`npm test`）で固定してあります。

全部の確認を飛ばす `--yolo` もありますが、中身を分かっている作業だけにしてください。

## 起動オプション

```
-p, --print <文>       一回だけ実行して終了
-m, --model <名前>     使うモデル（既定: qwythos:latest）
    --host <URL>       Ollama の場所（既定: http://localhost:11434）
    --ctx <数>         文脈の広さ（既定: 32768）
    --temp <数>        創造性の高さ 0〜1（既定: 0.3）
    --steps <数>       1回のお願いで許すツール実行の上限（既定: 40）
    --yolo             確認を全部飛ばす
    --no-think         思考モードを切る（速いが精度は落ちる）
    --show-thinking    考えている内容を全部表示
    --quiet-thinking   考えている様子を非表示
    --cwd <フォルダ>   作業フォルダを指定
    --allow-outside    作業フォルダの外も触れるようにする
    --no-net           ネット接続を切る（検索とページ取得の道具を渡さない）
    --plan             計画モードで始める（まず調べて方針を出す。書き換えない）
    --embed            別のアプリのエンジンとして動く（道具の実体は相手が持つ）
    --resume [ID]      前の会話の続きから
    --sessions         保存済みの会話を一覧
```

## 道具（ツール）

小さいモデルは選択肢が多いほど迷うので、数を絞っています。手元に6つ、外に4つ、段取りに3つ。
このうち実際に渡すのは、**そのとき呼べるものだけ**です（言語サーバーが無ければ `find_symbol` は渡しません）。

| 道具 | 役割 | 確認 |
| --- | --- | --- |
| `read_file` | ファイルを行番号つきで読む | なし |
| `list_dir` | フォルダの中身を見る | なし |
| `search_files` | 正規表現で横断検索（ripgrep があれば使用） | なし |
| `write_file` | ファイルを新規作成・全書き換え | あり |
| `edit_file` | ファイルの一部を厳密一致で置き換え | あり |
| `run_command` | シェルコマンドを実行 | 読み取り系以外はあり |
| `web_search` | ネットで調べる（Tavily） | あり |
| `web_fetch` | ページを1枚読んで文章にする | あり |
| `browse` | ログイン済みのブラウザでページを開く | あり |
| `todo_write` | やることリストを作る・進める | なし |
| `find_symbol` | 名前の定義・参照・型を意味で引く（LSP） | なし |
| `spawn_agent` | 調べものを別のエージェントに任せ、答えだけ受け取る | なし |
| `browser_login` | ブラウザを開いて、あなたが手でログインする | あり |

## 意味でコードを探す（LSP）

`search_files` は文字の一致しか見ません。`renderTodos` を探すと、**コメントに書かれた説明文まで当たります**。
`find_symbol` は言語サーバーに聞くので、その名前が実際に何を指すかを分かったうえで答えます。

```
❯ renderTodos がどこで定義されて、どこから使われているか調べて

● find_symbol({"name":"renderTodos","operation":"definition"})
  ⎿ 1 件
● find_symbol({"name":"renderTodos","operation":"references"})
  ⎿ 4 件

renderTodos は src/ui.mjs の 177 行目で定義されています。
使用場所は src/tools.mjs:934 と bin/qwc.mjs:632 です。
```

このリポジトリで実際に比べた結果です。

| | 当たった件数 |
| --- | --- |
| `search_files`（文字で探す） | 7件（**うち2件はコメント内の記述**） |
| `find_symbol`（意味で探す） | **4件**（本物の参照だけ） |

**遅いモデルほど効きます。** 候補から本物を選ぶ作業が要らなくなるぶん、往復が減ります。

`operation` は3つ。`definition`（定義の場所）／`references`（使われている場所）／`hover`（型と説明）。
渡すのは**名前だけ**です。行番号と桁をモデルに数えさせると1文字のズレで別物を指すので、位置の特定はこちら側でやります。

### 用意するもの

言語サーバーが要ります。**入っていない言語では道具そのものを渡しません。**

| 言語 | 入れ方 |
| --- | --- |
| TypeScript / JavaScript | `npm i -g typescript-language-server` |
| Rust | `rustup component add rust-analyzer` |
| C / C++ | `brew install llvm`（clangd） |
| Python | `npm i -g pyright` |
| Go | `go install golang.org/x/tools/gopls@latest` |

追加のライブラリは要りません。LSP は「ヘッダ＋JSON を標準入出力でやりとりする」だけの決まりごとなので、
`src/lsp.mjs` に素で書いてあります。

> **TypeScript 7 には `tsserver.js` がありません。** グローバルに TS7 が入っていると、
> あるように見えて動きません。qwc は自前の `node_modules` に 5.x を持っていて、
> 作業フォルダに無ければそちらを使います。

## 調べものを別のエージェントに任せる

「この機能がどこにあるか探して」を本体にやらせると、**読んだファイルの中身がそのまま会話に残ります**。
32k の文脈は数ファイルで埋まり、肝心の作業に入る前に要約が始まります。

`spawn_agent` は、その調べものを別のエージェントに投げます。
読んだファイルは向こうの会話にだけ溜まり、**本体に返ってくるのは答えの数行だけ**です。

```
❯ 実行前の確認をどこで決めているか調べて、そのうえで直して

● spawn_agent(実行前の確認が要るかどうかを、どのファイルのどこで決めているか)
┌ 調べてきてもらいます
│ ● search_files(approval:)
│ ● read_file(src/tools.mjs)
│ ● read_file(src/agent.mjs)
└ 3 回調べて戻りました
```

任された側の出力は `│` で一段下げます。誰がしゃべっているのか分からないまま道具の実行が流れると、
**本体が勝手なことを始めた**ように見えるからです。

### 実測（同じ問い・`qwythos:latest`・このリポジトリ）

「`src/tools.mjs` で、実行前の確認が always になっている道具を全部挙げて」を解かせた結果です。

| | 所要 | 本体に残った文脈 | 本体が読んだ token | 答え |
| :--- | ---: | ---: | ---: | :--- |
| 自分で読む（1回で読み切ろうとした） | 276秒 | 15,897文字 | 9,607 | **6つ中2つ**（誤り） |
| 自分で読む（7回に分けて読んだ） | 135秒 | 12,945文字 | 32,467 | 6つとも正しい |
| **任せる（`spawn_agent`）** | 164秒 | **4,351文字** | **5,058** | 6つとも正しい |

**本体に残るのは3分の1以下**です。差はこのあと効いてきます。会話は毎ターン丸ごと送り直すので、
残った文脈は最後まで払い続けることになるからです（`5,058` と `32,467` の差がそれです）。
所要時間はほとんど変わりません。任された側も同じモデルを使うので、**手間が消えるわけではなく、置き場所が変わります**。
上の数字はモデルが常駐している状態のものです（1ファイル調べて答えるだけなら、任せて戻るまで通しで56秒でした）。
読み込みからだと数分待たされますが、それは任せたかどうかとは関係ありません。

上の1行目は、45KBのファイルを一度に読もうとして**切り詰めに気づかないまま**前3分の1だけで答えた例です。
省略の断り書きを「**これは全部ではない**」と分かる書き方に直しました（→[長すぎる出力の切り詰め](#モデルの癖への対処)）。

任された側は**読むことしかできません**。書き換える道具は最初から渡していません。
2つのエージェントが同じファイルを同時に書いたら、どちらの結果も信用できなくなるからです。
`spawn_agent` 自身も渡していないので、入れ子には広がりません。

立場が違うので、**指示文ごと差し替えています**。本体の指示には「変更したファイルを報告せよ」が入っていて、
何も変更できない相手にそれを渡すと、変更していないのに変更したと書いて戻ってきます。

> **小さいモデルは自分からは使いません。** 実測では、頼まない限り自分で読みにいきました。
> 「別の担当に任せて」と日本語で頼んでも自分でやってしまいます。
> **`spawn_agent` という名前を出して**頼んだときだけ、確実に任せました。

## 別のアプリの中でエンジンとして使う（`--embed`）

qwc の値打ちは、道具そのものではなく**輪のほう**にあります。
考える→道具を使う→結果を見る、の繰り返しと、そこに積んだ受け皿
（本文救済・促し・やることリスト・計画モード・調べものの委譲）が中身です。

ところが、これを別のアプリに入れようとすると道具で行き詰まります。
入れる先にはたいてい**自前の作法**があり、qwc が自分で `fs.writeFileSync` を呼んだ時点でその約束は破れます。

そこで `--embed` では、**道具の実体をぜんぶ相手に返します**。
qwc は「`read_file` をこの引数で呼びたい」と言うだけで、実際に読むのは相手のアプリです。

| | どちらが持つか |
| :--- | :--- |
| 輪・指示文・受け皿・やることリスト・調べものの委譲 | **qwc** |
| 道具の実体・権限・記録 | **相手のアプリ** |

行ごとの JSON を標準入出力でやりとりします（JSON Lines）。追加のライブラリは要らず、どの言語からでも読めます。

```
相手 → qwc   {"type":"hello","tools":["read_file","list_dir"],"root":"/path","model":"qwythos:latest"}
相手 → qwc   {"type":"user","text":"担当者の名前を全部調べて"}
qwc  → 相手  {"type":"tool_request","id":"t1","name":"list_dir","args":{"path":"."}}
相手 → qwc   {"type":"tool_result","id":"t1","output":"売上4月.md\n売上5月.md","isError":false}
qwc  → 相手  {"type":"turn_end","text":"佐藤さんと鈴木さんです。"}
```

- **相手が `hello` で名乗った道具だけをモデルに見せます。** 相手が持っていない道具を見せると、
  モデルは呼んで断られ、その理由を考えるのに往復を1回使います
- `todo_write` と `spawn_agent` は外に触れないので、**相手の実装が要りません**。輪と一緒に付いていきます
- 確認は持ち主の仕事なので、こちらでは聞きません（同じことを二度聞かれないため）
- 画面表示は**標準エラー**に寄せます。標準出力に1文字でも混ざると相手が JSON を読めなくなります。
  捨てないのは、動かないときに何も分からなくなるためです
- **相手がいなくなったら、こちらも終わります。** 残っているとモデルを抱えたまま居座ります

実際の利用例は Omnical AI です。あちらは「ファイルに触れる処理は必ず安全層を通す」という約束を持っているので、
qwc は道具を持たないまま輪だけを回し、読み書きはあちらの安全層が引き受けています。

## 打ちやすくする工夫

### `@` でファイルを渡す

場所が分かっているなら、探させずに直接渡したほうが速く、間違いません。

```
❯ @src/agent.mjs の runTurn を短くして
  @src/agent.mjs を添えました（18,204文字）
```

**道具の往復が2回減ります**（`search_files` → `read_file` を省ける）。実測で、
渡したときは道具を1度も呼ばずに答えました。

作業フォルダの外（`@../../.ssh/id_rsa` など）は断ります。読めなかったものは理由つきで出すので、
黙って無視されることはありません。

### `@` で画像も見せられる

スクリーンショットをそのまま渡せます。**目を持つモデル**（`gemma4:26b` など）が要ります。

```
❯ @screen.png この画面に何が写っているか3行で教えて
  @screen.png を画像として見せます（428KB）

「Omnical AI」という、AIを使って様々なタスクをこなすためのインターフェース画面です。
中央には質問や要約、メール作成、思考の整理といった機能が配置されています。
左側には、フォルダ管理、読み込んだ書類、保存した会話などのツールメニューが並んでいます。
```

（実際のスクリーンショットで確認した出力です）

目のないモデルのときは、送らずに理由を出します。

```
! @screen.png は渡せませんでした（いまのモデルは画像を見られません（-m gemma4:26b などで試せます））
```

対応するのは `.png .jpg .jpeg .gif .webp .bmp`、1枚 8MB まで。
**画像は直近の1発言にだけ残します**（1枚で文脈をかなり食うため、古いものは自動で落とします）。
会話の記録にも中身は保存せず、「画像を見せた」という事実だけを残します。

### `/名前` で決まった依頼を呼ぶ

`.qwythos/commands/名前.md` を置くと `/名前` で呼べます。中身がそのまま依頼になります。

```markdown
<!-- .qwythos/commands/review.md -->
# 変更を見直す
直近の変更を確認して、抜けている検証と危ないところを指摘してください。
$ARGUMENTS
```

```
❯ /review 認証まわりを重点的に
  /review — 変更を見直す
```

`$ARGUMENTS` に引数が入ります（書き忘れた場合は末尾に足されます）。1行目の見出しは説明として使われ、
本文からは外れます。`~/.qwythos-code/commands/` に置けばどのプロジェクトからでも使え、
同じ名前なら作業フォルダ側が優先されます。一覧は `/commands`。

### モデルは入っているものから選びます

指定されたモデルが無いとき、エラーで止まらずに、入っているものから妥当なものを選びます
（埋め込み専用は除外）。既定は `qwythos:latest` です。

> **9B を既定にした理由。** 同じ作業（5手のテスト修正）で **9B は30秒、14B は10分超**でした。
> 大きいほど自律的に動けるわけでもありません（→「モデルの癖への対処」）。

### 実測で比べたモデル

| モデル | 1手あたりの思考 | 完走 | 画像 | 備考 |
| --- | ---: | :---: | :---: | --- |
| `qwythos:latest`（9B） | 3〜9秒 | ✅ | ✗ | 既定。7.4GB と軽い |
| **`gemma4:26b`（MoE）** | **0.6〜3秒** | ✅ | **✅** | **一番速い。**17GB 必要 |
| `qwen3:14b-q4_K_M` | 遅い | △ | ✗ | 5手の作業が10分超で終わらず |
| `qwen2.5-coder:14b` | ― | △ | ✗ | 道具を呼ばず本文にJSONを書く（対策済み） |

メモリに余裕があるなら `gemma4:26b` が速くて賢いです。`-m gemma4:26b` で試せます。

> `gemma4:26b` は日本語で頼んでも英語で返してきました。指示文の**末尾**に言語の念押しを
> 置いて直しています（指示は最後にあるものほど効きます）。

## やることリストと計画モード

長い作業になると、小さいモデルは途中で「何を頼まれていたか」を見失います。
段取りを紙に書き出させて、そこへ何度でも戻れるようにしてあります。

### やることリスト

3手を超える作業では、モデルが自分でリストを作って進めます。

```
● やること (1/3)
  ☑ b.js の引き算を足し算に直す
  ▸ c.js の引き算を足し算に直す
  ☐ npm test 実行
```

いま手をつけているものだけが太字になります。`/todo` でいつでも見返せます。

> **頼むだけでは呼びません。** 実測（qwythos 9B）で、5手で終わる作業では
> 指示しても `todo_write` を呼びませんでした。短い作業ならそれで困らないので放っておき、
> **道具を6回使ってもリストが無いときだけ、1度だけ促します**。
> 促したあとは自分で更新しながら最後まで走りました。毎回促すと、そのぶん往復を食って本来の作業が進みません。

### 計画モード

いきなり書き換えられると困るときは、先に方針だけ出させます。

```
❯ /plan
  ✓ 計画モードに入りました。
    書き換えとコマンド実行の道具を外しました。まず調べて、方針を出します。

❯ 認証まわりをリファクタしたい

（調べたうえで方針を出す）

┌ この方針で進めますか
└ y = 実行に移る / n = このまま相談を続ける
```

`y` を押すと道具が戻り、その方針のまま実行に移ります。`n` なら計画モードのまま相談を続けられます。

**「使わないでください」と頼むのではなく、道具そのものを外しています。** `write_file` と `edit_file` は
モデルに渡らず、`run_command` も読み取り専用のものしか実行しません。頼むだけでは、小さいモデルは守りません。

`--plan` を付けて起動すれば、最初から計画モードで始まります。

## ネットにつながる部分

手元のモデルは学習した時点までのことしか知りません。ライブラリの新しい版・見たことのないエラー・
API の細かい仕様は、調べたほうが確実です。そのための道具が3つあります。

### 何が出ていくか

| 道具 | 出ていくもの |
| --- | --- |
| `web_search` | 検索の言葉だけ |
| `web_fetch` | URL だけ |
| `browse` | URL と、**そのサイト向けに保存済みの Cookie**（ログイン状態を使うため） |

**どの道具でも、ファイルの中身・会話の履歴・作業フォルダの場所・鍵は送りません。**
外に出る処理は `src/web.mjs`（検索・取得）と `src/browser.mjs`（ブラウザ）の2ファイルだけなので、
そこを読めば全部確かめられます。

### 使う前に必ず聞きます

ネットに出る3つは、書き換えと同じく**実行前に確認**します。何を検索するか・どこを開くかが
画面に出てから決められます。

```
┌ 確認 ネットで検索します
│   Node.js 24 fetch stable
│   この言葉が検索サービス（Tavily）へ送られます
└ y = 実行 / n = やめる / a = 以後このセッションは同種を自動許可
```

`a` を押せば、そのセッション中は聞かれなくなります。`--no-net` を付けて起動すれば、
道具そのものを渡さないので、モデルは存在すら知りません。

### 手元や社内のアドレスは読みません

`web_fetch` は公開されたページ専用です。次は断ります。

- `localhost` / `127.0.0.1` / `::1`
- 私有アドレス（`10.x` / `172.16〜31.x` / `192.168.x`）
- リンクローカル `169.254.x`（**クラウドの資格情報が置いてある場所**）
- `.local` / `.internal` で終わる名前
- `http` `https` 以外（`file://` など）

転送（リダイレクト）された先も、最後にもう一度調べます。指示文に URL を書くだけで
手元のサービスを叩かせる、という筋を塞ぐためです。

## ログインが要るサイトを読ませる

社内 Wiki、GitHub の非公開リポジトリ、管理画面。`web_fetch` ではログイン画面しか取れません。
そういうページは、**あなたが普段使うのと同じ本物のブラウザ**で開きます。

### やりかた

```
❯ /login github.com

  ブラウザを開きます。表示された画面で、いつも通りログインしてください。
  qwc はパスワードを受け取りません。終わったらここで Enter を押してください。
  → ログインが終わったら Enter
  ✓ github.com のログイン状態を保存しました（Cookie 14 件）。
```

以後は、頼むだけで読めます。

```
❯ このPRの説明を要約して https://github.com/…/pull/12

● browse(https://github.com/…/pull/12)
  ⎿ Fix the retry loop by …
```

| コマンド | 何をするか |
| --- | --- |
| `/login <サイト>` | ブラウザを開いて手でログインし、その状態を保存する |
| `/logins` | ログイン状態が残っているサイトの一覧（値は出しません） |
| `/logout` | 保存したログイン状態をすべて消す |

### パスワードは受け取りません

**qwc はパスワードを保存しません。求めもしません。** 入力するのは本物のブラウザの画面で、
qwc はそのキーボード入力にも画面の中身にも触りません。

残るのは `~/.qwythos-code/browser/`（`700`）で、中身はブラウザが管理する形の Cookie と
localStorage です。これは**あなたのログイン済みセッションそのもの**なので、
共用のパソコンでは使い終わったら `/logout` してください。

### 自動化と気づかれないようにしています

画面なしのブラウザは、既定では「自動で動かしています」と自分から名乗ります
（`navigator.webdriver` が `true`、UA に `HeadlessChrome`）。
これを見て**ログインし直しを迫るサイトがある**ため、名乗りだけをふつうのブラウザに揃えてあります。

| | 直す前 | 直した後 |
| --- | --- | --- |
| `navigator.webdriver` | `true` | `false` |
| UA | `HeadlessChrome/151…` | `Chrome/151…` |

あなた自身のブラウザで、あなた自身のアカウントの、あなた自身のページを開くためのものです。
**それでも見破って断るサイトはあります**し、サイトの利用規約に反する使い方をしてよいという意味でもありません。

### 残るログイン・残らないログイン

実測で確かめた挙動です。

| 種類 | ブラウザを閉じたあと |
| --- | --- |
| 有効期限つき Cookie（「ログインしたままにする」） | **残ります** |
| localStorage に入るトークン（最近のWebアプリ） | **残ります** |
| セッション Cookie（期限なし） | 消えます（ブラウザの仕様） |

3つ目に当たるサイトは、`/login` してもすぐ切れます。そのときは使うたびに `/login` してください。

### `web_fetch` との使い分け

| | `web_fetch` | `browse` |
| --- | --- | --- |
| 速さ | 速い（0.2秒程度） | 遅い（1〜2秒＋起動） |
| ログイン | 使えない | **使える** |
| JavaScript で描くページ | 読めない | **読める** |
| `localhost` / 手元の開発サーバー | 断る | **開ける** |

公開ページは `web_fetch` を先に使うようモデルへ指示してあります。`browse` は、
それで足りなかったときの手段です。

> `browse` が手元のアドレスを開けるのは意図した違いです。`localhost:3000` の画面を
> 見てもらう用途が実際に多いためです。開く前に必ず URL を見せて確認します。

### 用意するもの

ブラウザ操作にだけ Playwright が要ります。**入っていなければ `browse` はモデルに渡らず**、
それ以外の機能はそのまま動きます。

```bash
cd ~/qwythos-code
npm install playwright && npx playwright install chromium
```

### 検索の鍵

`web_search` には Tavily の鍵が要ります。次のどちらかで用意してください。

```bash
export TAVILY_API_KEY=...            # 起動するシェルに置く
# または
echo 'TAVILY_API_KEY=...' > ~/.qwythos-code/.env && chmod 600 ~/.qwythos-code/.env
```

**鍵が無いときは `web_search` をモデルに渡しません。** 呼べない道具を見せて失敗させないためです
（`web_fetch` は鍵が要らないので使えます）。他のアプリの設定ファイルは読みに行きません。

## 迷子にならないための工夫

9B という小さめのモデルでも最後まで走り切れるように、輪の側で支えています。

- **同じ呼び出しの繰り返しを検知**し、3回目で止めて「別の手を考えて」と差し戻します
- **ツールの出力が長すぎるときは真ん中を省略**して、文脈の枠を食いつぶさないようにします
- **文脈が7割を超えたら**、まず古いツール出力を短くし、それでも足りなければ会話を自動で要約します
- **ツール実行の往復に上限**（既定40回）を設け、無限に走り続けないようにします
- **`edit_file` の失敗は理由つきで返す**ので、モデルが自分で直せます
- **本文に書かれた道具の呼び出しを拾います**（後述）
- **「やります」と言うだけで動かないとき、その場で促します**（既定5回まで）
- **長くなってきたのにやることリストが無ければ、1度だけ促します**（既定6手め）
- **調べものは別のエージェントに任せられます**（`spawn_agent`・読んだ中身は本体に残りません）

## モデルの癖への対処

ローカルのモデルは、道具の使い方に癖があります。実測で見つけたものと、その対処です。

### 道具を呼ばずに本文へJSONを書く

`qwen2.5-coder:14b` は `ollama show` で「tools 対応」と出ますが、実際には決められたタグ
（`<tool_call>`）を付けずにJSONを本文へ書きます。Ollama は解釈できず、道具は永遠に呼ばれません。

そこで本文からJSONを拾います。裸のJSON・` ```json ` フェンス・`<tool_call>`タグ・配列の4形式に対応し、
**ふつうの文章や、知らない道具名は拾いません**（誤って実行しないため）。
一度拾ったモデルでは、以後そのセッション中は本文を出す前に必ず見分けます（画面にJSONを晒さないため）。

**関数を書くような形もあります。** `qwythos:latest` にこちらから道具の名前を出して頼むと、
その名前を `spawn_agent(task="…")` と文章に書き写して手を止めました（実測・2回とも）。
JSONではないので上の受け皿では拾えません。これも拾いますが、**3つとも満たすものだけ**にしています。

1. 行の先頭から始まっている（文の途中で触れただけのものは取らない）
2. 名前がいま渡している道具のもの
3. **引数の名前が、その道具が実際に持っている引数と一致する**

3つめが効きます。`spawn_agent(task=…)` は通り、`これは spawn_agent(便利です)` は通りません。
` ``` ` で囲まれた中も見ません。書き方の例を見せているだけで、実行してほしいわけではないからです。

### 手順を述べるだけで手を動かさない

「まず〇〇します」「次にテストを実行します」と書いて、道具を呼ばずにターンを終えるモデルがあります。
待っていても永遠に動かないので、その場で促します。

判定は**最後の一文**で行います。「直しました。次にテストを実行します。」のように完了報告と次の宣言が
同居することがあり、全文で見ると完了報告に引きずられて「終わった」と誤認するためです。
逆に、正しい完了報告を促してしまうと同じ話を蒸し返すので、そこは促しません。

### 実測（同じ課題・`qwen2.5-coder:14b`）

「テストを実行して、失敗しているなら直して、通ることを確認して」を繰り返した結果です。

| 対処 | 結果 |
| :--- | :--- |
| 何もしない | 道具を呼べず**何も起きない** |
| 本文からJSONを拾う | 3回中1回成功 |
| ＋ 促し（上限2回） | 修正は入るが、確認まで届かない |
| ＋ 促し（上限5回・最後の一文で判定） | **修正 → テスト実行 → 合格の報告まで完走** |

`qwythos:latest`（9B）は、これらの対処なしで同じ課題を2回とも完走しました。
**モデルが大きいほど自律的に動けるとは限りません。**

### 切り詰めたことに気づかない

道具の出力が長いときは、真ん中を省いて前後を残します（既定12,000文字）。
ところが 9B は、その断り書きを読み飛ばして**全部を見たつもりで答えます**。
45KBのファイルを一度に読ませたら、前3分の1だけを見て「該当は2つです」と答えました（本当は6つ）。

そこで断り書きを、何が起きたかだけでなく**次に何をすればよいか**まで書く形に変えました。

```
…[28537 characters omitted from the middle. THIS IS NOT THE WHOLE OUTPUT —
do not conclude anything about the omitted part. If it matters, read it with
offset/limit or narrow your search.]…
```

### 長い文脈で必ず落ちる問題（修正済み）

**いまは `fetch` を使っていないので、300秒で切れることはありません。**以下は、そう作り替えた理由です。

Node に最初から入っている `fetch` は、**応答の1文字目が返るまで300秒で必ず諦めます**。
この値を設定で伸ばす方法は公開されていません。クラウドのAPIなら妥当な線ですが、手元のモデルには短すぎます。

実測では、**12,668トークンの依頼が301秒ちょうどで `fetch failed` になりました**（`UND_ERR_HEADERS_TIMEOUT`）。
**Ollama 側は無事で、こちらが先に諦めていた**だけです。
暖まっていれば前処理は毎秒500トークンほど出ますが、モデルの読み込みや文脈枠の取り直しが挟まると
最初の1文字までが分単位になります。ファイルを1つ読ませれば届く長さなので、少し長い作業をすると踏みます。

そこで、長くなる2か所（`chatStream` と `chatOnce`）だけ `node:http` で投げ直しています。
追加のライブラリは要りません。待ち方は2段階です。

| いつ | 待つ長さ | 考え方 |
| :--- | :--- | :--- |
| 1文字目が出るまで | 15分 | 長い文脈の下ごしらえをしているだけかもしれない |
| 出はじめたあとで途切れたら | 3分 | 途中で止まったのなら、待っても戻らない |

どちらも `Ctrl+C` でいつでも止められます。

```bash
cd ~/qwythos-code

## 設定ファイル

`~/.qwythos-code/config.json` に置くと、既定値を変えられます。
`/save` を使うと、いまの設定がそのまま書き出されます。

```json
{
  "model": "qwythos:latest",
  "numCtx": 32768,
  "temperature": 0.3,
  "maxSteps": 40,
  "showThinking": "compact"
}
```

会話の記録は `~/.qwythos-code/sessions/` に残ります。`qwc --resume` で続きから再開できます。

## プロジェクトごとの指示

作業フォルダに `QWYTHOS.md`（または `AGENTS.md` / `CLAUDE.md`）があれば、
その中身を毎回読んでから作業します。コーディング規約やテストの走らせ方を書いておくと従います。
`/init` で叩き台を作れます。

## 構成

```
bin/qwc.mjs        入り口。オプション解釈と対話ループ
src/agent.mjs      「考える→道具を使う→結果を見る」の輪
src/ollama.mjs     Ollama との通信（逐次受信）
src/web.mjs        ネットに出る場所（検索・ページ取得・URLの検査）
src/browser.mjs    ログイン済みブラウザの操作（Playwright・任意）
src/tools.mjs      11個の道具の中身
src/subagent.mjs   調べものを任せる別のエージェント
src/embed.mjs      別のアプリの中でエンジンとして使われるための口（--embed）
src/mentions.mjs   @パス を中身・画像に差し替える
src/commands.mjs   自分で作るスラッシュコマンド
src/lsp.mjs        言語サーバーとのやりとり（依存なし）
src/permissions.mjs 実行前の確認
src/prompt.mjs     行動ルール（システムプロンプト）
src/paths.mjs      作業フォルダの外に出ない仕組み

src/ui.mjs         色・差分・スピナーなどの表示
test/run.mjs       モデル不要の自動検証
```

## 実測（qwythos:latest / Apple Silicon）

- 生成速度: 約17トークン/秒
- **前処理（送った文を読む速さ）: 暖まっていれば毎秒500トークンほど**
  （2,059トークンで4.0秒。同じ相手に続けて聞けば2回目は0.4秒＝前の分は覚えている）
- 初回のモデル読み込み: 約81秒（以後は `keep_alive` で30分常駐するため待ち時間なし）
- 「2ファイルにまたがる関数追加 → テスト実行 → 失敗を自力修正 → 合格」までを、
  ツール実行9回・約2分で完走することを確認済み

**待たされるときは、たいていモデルの読み込みです。** 生成も前処理も上の速さで出ているのに
体感が遅いなら、直前に別のモデルを使ったか、しばらく空いて常駐が切れたかを疑ってください。
